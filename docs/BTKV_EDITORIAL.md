# BTKV v2: technical completion and editorial queue

The current bank contains exactly 150 original practice SBAs, written for education, not official PPDS questions. No human medical peer review has been performed. Every record remains `needs_review`, with `human_medical_review_required` and `source_not_verified` flags. The app displays this status after an answer or exam submission.

Each category contains 50 questions, divided into ten five-question topics. Per category: 15 easy, 25 medium, 10 hard; 35 clinical vignettes, 10 basic concepts, 5 data interpretations; 10 keys each at A/B/C/D/E. These classifications are author judgments that also need editorial calibration. Automated distribution checks cannot establish question difficulty, clinical validity, adequate information, or a uniquely defensible answer.

## Source verification

Requests to the supplied PubMed source were denied by the environment network policy (HTTP CONNECT 403). The supplied EACTS and ESC URLs are retained only as **unverified starting points**. No DOI, edition, page number, guideline version currency or claim of source support was invented. A repeated broad guideline pointer is not a verified per-question citation; some foundational anatomy and trauma questions will require different sources. Reference notes state this limitation explicitly.

A clinician/editor must check each question's claims against appropriate current authoritative sources, add exact verified references, and document any resource-dependent decisions or guideline disagreements. Do not promote a question to approved/published simply because technical validation passes. Doses and unsupported procedural thresholds were deliberately avoided; the remaining numeric examples still require clinical and factual review.

## Review checklist

For each ID, check:

- Vignette consistency: timeline, physiology, comorbidities, imaging, laboratory and hemodynamic data.
- Sufficiency and clarity: one decision, enough information, no assumption that changes the answer.
- Five comparable, clinically relevant options with exactly one best answer in the stated context. Distractor plausibility and answer-length cues need manual calibration.
- Explanation, correct-answer reason, clinical reasoning, every distractor rationale and clinical pearl agree. Some fields express the same teaching point; editors may expand them into distinct explanations where useful.
- Learning objective, topic/subtopic, format and difficulty genuinely fit the content.
- Verify the exact source, date/version, claim relevance and permitted paraphrase; record disagreements instead of turning contested recommendations into an unqualified SBA.

`docs/btkv-validation.json` records technical counts, similarity candidates and all flagged IDs. The current token-set similarity threshold is 0.60; an empty suspicious-pair list is not proof against conceptual repetition. The report is deterministic and regenerated by `npm run validate:btkv`.

## Backward compatibility

The previous 30 introductory BTKV records are retained in `src/data/legacy/btkv-v1.json`, outside the active question glob. They are not counted as part of the 150 new records or copied into LocalStorage. The session resolver includes the archive so existing attempts retain their original question text and keys. Existing answer history is retained. New mastery counts use current question IDs; old answers are not falsely mapped onto different new questions. Old bookmarks and notes have a read-only archive in Profile.

Additive schema fields and optional scoring preserve v1/v2 learning backups and original LPDP/SIMAK records. Legacy `reviewed` values remain readable for compatibility; the strict BTKV validator only accepts the new editorial workflow. JSON and CSV export/import preserve clinical metadata. BTKV-v2 imports use the strict content schema; legacy imports remain compatible.

## Learning and tryout behavior

Materi supports category, topic, difficulty and incorrect-answer filters and sessions of 5/10/20/30/50 questions. Subject cards show current completion, accuracy and difficulty counts, with a start button. Tryout provides three category packages and a mixed BTKV package. The controls configure question count, minutes, and correct/wrong/blank practice points; attempts persist those settings. These are practice settings with no claim of official PPDS scoring or timing. Explanations, clinical pearls and source links remain hidden until a study answer or final exam submission.

LPDP and SIMAK files remain unchanged. Their outstanding 320 questions remain outside this BTKV change; the original global 550-question gate still fails until those banks are completed.
